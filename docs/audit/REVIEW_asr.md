## 2) 详细分析与修复建议

### 1. [HIGH] 可预测临时文件名导致竞态/覆盖/串话风险
- **位置**：278-280, 321-329
- **问题**：`out_base = temp_dir()/whisper_out_{stem}`。同名音频并发转写会写入同一目标，可能互相覆盖、读到他人结果，或删除他人 `.srt`。
- **影响**：错误字幕、数据串话、并发不安全。
- **建议**：
  - 使用唯一目录/文件名（UUID、`tempfile::Builder`、随机后缀）。
  - 每次任务独立工作目录，结束后递归清理。

### 2. [HIGH] 本地 whisper 子进程无超时/取消控制，可无限挂死
- **位置**：298-306
- **问题**：`Command::output()` 阻塞等待直到进程退出；无 timeout、无 kill 策略。
- **影响**：任务卡死、线程池占用、用户无法恢复。
- **建议**：
  - 改为 `tokio::process::Command` + `tokio::time::timeout`。
  - 超时后 `child.kill().await` 并返回明确错误。
  - 支持上层取消信号。

### 3. [HIGH] 整文件 base64 一次性加载
- **位置**：125-129
- **问题**：完整读取音频到内存，再 base64（约额外 33% 膨胀），JSON 再拷贝一次。
- **影响**：大文件内存峰值高、OOM、请求体过大被服务端拒绝。
- **建议**：
  - 增加文件大小上限（如 25MB/50MB 可配置）。
  - 超限时提前报错并提示先压缩/切片。
  - 如 API 支持，优先 URL 上传或分片上传而非 data URI。

### 4. [MEDIUM] 错误回显可能泄露隐私内容
- **位置**：169-170
- **问题**：JSON 解析失败时拼接 `raw=<前400字符>`；响应可能含转写文本/敏感信息。
- **影响**：日志或前端错误弹窗泄露用户音频内容。
- **建议**：
  - 默认不回显原文；仅记录长度、状态码、trace id。
  - 加“调试模式”开关才允许截断回显。

### 5. [MEDIUM] `unwrap()` panic 路径
- **位置**：339
- **问题**：`Regex::new(...).unwrap()` 理论上可能 panic（未来修改 regex 字面量时尤甚）。
- **影响**：单点 panic 直接终止当前流程。
- **建议**：
  - 使用 `once_cell::sync::Lazy<Result<Regex, _>>` 初始化并在失败时转 `AsrError::Invalid`。
  - 或 `expect("valid timestamp regex")`（至少可诊断）。

### 6. [MEDIUM] 进程输出全量收集可能内存压力
- **位置**：299-303, 309-312
- **问题**：`output()` 会把 stdout/stderr 全读入内存。
- **影响**：异常情况下日志爆量触发内存占用。
- **建议**：
  - 将 stdout/stderr 重定向到文件或按行限流读取。
  - 错误消息只保留前 N KB。

### 7. [MEDIUM] 临时产物清理不完整
- **位置**：321-331
- **问题**：仅在读完后尝试删除 `.srt`；失败路径或其它扩展产物（若 whisper 输出）未清理。
- **影响**：磁盘垃圾累积、隐私文件残留。
- **建议**：
  - `scopeguard`/RAII 清理策略，确保成功/失败都执行清理。
  - 使用独立 temp 目录并 `remove_dir_all`。

### 8. [LOW] API key 仅判空
- **位置**：120
- **问题**：`"   "` 会通过校验，导致无效请求。
- **建议**：`if api_key.trim().is_empty()`。

### 9. [LOW] language 未校验
- **位置**：292-295
- **问题**：虽然未经过 shell（无传统命令注入），但可传入异常值影响 CLI 参数语义。
- **建议**：
  - 仅允许 `^[a-zA-Z-]{2,12}$` 或受控枚举（`zh`,`en`...）。
  - 无效值回退 `None` 或返回错误。

## 3) 专项结论

### 子进程注入
- **结论**：当前使用 `Command::new(...).args(...)`，不经 shell，**经典 shell 注入风险较低**。
- **但**：仍存在参数语义污染与资源控制问题（超时/并发/输出内存）。

### HTTP 请求安全
- **优点**：HTTPS 固定基址、`bearer_auth`、统一超时（180s）。
- **不足**：无重试/退避、错误回显隐私、请求体体积无上限控制。

### base64 编解码
- **结论**：编码逻辑本身正确；主要风险在**内存占用与超大 payload**，不是算法错误。

### 错误传播
- **优点**：大多数路径返回 `Result`，错误可上抛。
- **不足**：仍有 `unwrap()`；错误分类中 `Io` 与 `Local` 语义略混杂。

### 竞态条件
- **结论**：本地临时文件命名策略存在实际竞态，需优先修复。
